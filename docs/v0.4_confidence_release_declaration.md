## 2. v0.4 Confidence Definition

### What Confidence Is NOT
- `confidence_reason` is **not** a judgment about correctness
- `confidence_reason` is **not** a numerical score
- `confidence_reason` is **not** a prediction or recommendation
- `confidence_reason` is **not** mutable after generation

### What Confidence IS
- `confidence_reason` is a **state description snapshot**
- `confidence_reason` is a **human-readable audit trail**
- `confidence_reason` is **non-numeric, non-evaluative, non-hierarchical**
- `confidence_reason` is **immutable once logged**

### Core Properties
1. **Non-numeric**: No digits, fractions, percentages, or scores
2. **Non-evaluative**: No good/bad, high/low, strong/weak assessments
3. **Non-hierarchical**: No levels, tiers, ranks, or stages
4. **Repeatable**: Same observation → same reason
5. **Auditable**: Reproducible from observation keys alone
6. **Optional**: Empty string is valid (PR21 absence semantics)
7. **Immutable**: Never regenerated, corrected, or reinterpreted

---

## 3. Structure Fixed (PR27)

### 4-Section Structure
```
Source:<text>; Stability:<text>; Consistency:<text>; Completeness:<text>
```

This structure is **permanent and non-negotiable**:
- 4 sections exactly
- Order is fixed: Source → Stability → Consistency → Completeness
- Section separator: `; ` (semicolon + space)
- Key-value separator: `:` (colon, no space)

Any violation of this structure is detected by PR31 Compliance Guard.

### Section Meanings
- **Source**: Which observation keys are present
- **Stability**: Temporal context availability
- **Consistency**: Core signal coverage
- **Completeness**: Observation breadth

---

## 4. Vocabulary Frozen (PR29B / PR30)

### Allowed Vocabulary (Exhaustive)

**Stability** (2 values):
- `temporal indicators present`
- `temporal indicators absent`

**Consistency** (3 values):
- `all core signals present`
- `some core signals present`
- `no core signals present`

**Completeness** (3 values):
- `temporal and current observations`
- `current observations only`
- `no observations`

**Source** (rule):
- Alphabetically sorted, comma-separated list of observation key names
- No summarization, aggregation, or evaluation

### Prohibited Vocabulary (Hard Ban)
The following terms are **permanently prohibited** in `confidence_reason`:

**Numeric/Quantitative**:
- Any ASCII digits: `0-9`
- Fractions, percentages, ranges
- Counts: "N fields", "N signals"

**Evaluative/Comparative**:
- good/bad, high/low, strong/weak
- sufficient/insufficient, reliable/unreliable
- complete/incomplete, rich/sparse
- better/worse, more/fewer

**Mathematical/Statistical**:
- compute, calculate, derive, formula
- scale, normalize, threshold
- weight, score, level, tier, rank
- probability, likelihood, confidence level

**Placeholder/Undefined**:
- TBD, TODO, placeholder
- None, null, N/A, undefined
- "not yet implemented"

This vocabulary is **frozen forever** for v0.4.

Future versions (v0.5+) may define new vocabulary, but v0.4 vocabulary never changes.

## 5. Detection and Audit (PR31–PR32B)

### Compliance Guard (PR31)
`validate_confidence_reason()` detects:
- PR27 structure violations
- PR30 vocabulary violations
- Hard ban violations (digits)

### Runtime Wiring (PR32)
Compliance validation runs after every `confidence_reason` generation.

Violations output warnings:
```
[WARNING][PR31][confidence_reason] violations=<...> ts=<...>
```

### Properties
- **Warning-only**: Never stops execution
- **Non-fatal**: Never affects behavior
- **Auditable**: Logged to stdout for monitoring

## 6. Snapshot Immutability (PR33)

### Snapshot Fields
Every `confidence_reason` is logged with immutable metadata:
```json
{
  "confidence_reason": "<frozen content>",
  "confidence_reason_version": "v0.4",
  "confidence_reason_generated_at": "<UTC ISO-8601 timestamp>"
}
```

### Immutability Guarantees
1. **Never regenerated**: Once logged, frozen forever
2. **Never corrected**: No post-hoc modifications
3. **Never reinterpreted**: Version locks semantics
4. **Never evolved**: v0.4 spec is permanent

### Provenance
- `version`: Which specification generated this reason
- `generated_at`: Exact UTC moment of generation
- `reason`: The immutable snapshot content

This enables:
- **Audit compliance**: Reason + version + timestamp = complete provenance
- **Legal defensibility**: Immutable historical record
- **Reproducibility**: Can verify reason was generated by v0.4 spec
- **Evolution separation**: v0.5+ cannot modify v0.4 reasons

## 7. Prohibited Actions (Hard Non-Goals)

v0.4 Confidence **will never**:

1. **Influence decisions**: Confidence never changes intent, overlay, or target_weight
2. **Produce numbers**: No scores, percentages, levels, or metrics
3. **Make judgments**: No evaluations of "good enough" or "trustworthy"
4. **Self-optimize**: No learning, tuning, or adaptation
5. **Regenerate**: Once logged, reason is permanent
6. **Correct itself**: No post-hoc fixes or normalizations
7. **Predict**: No forward-looking assessments
8. **Control**: No gates, guards, or execution flow changes

### Why These Are Prohibited
- **Influence decisions**: Confidence is explanation, not control
- **Produce numbers**: Numbers imply quantification, which breaks audit transparency
- **Make judgments**: Judgments introduce bias and interpretation
- **Self-optimize**: Optimization breaks immutability
- **Regenerate**: Regeneration breaks provenance
- **Correct itself**: Corrections break audit trail
- **Predict**: Predictions are not explanations
- **Control**: Control breaks READ-ONLY requirement

## 8. Positioning and Future

### v0.4 Confidence Role
v0.4 Confidence is the **explanation layer foundation**.

It is **not**:
- The intelligence layer
- The optimization layer
- The prediction layer
- The control layer

It **is**:
- The audit layer
- The transparency layer
- The explanation layer
- The immutability layer

### Future Evolution (v0.5+)
Future versions may:
- Add new observation sources (within PR25 categories)
- Improve semantic richness (within PR30 vocabulary constraints)
- Add new explanation dimensions (as new fields, not modifications to v0.4 fields)

Future versions **may not**:
- Modify v0.4 structure (PR27)
- Change v0.4 vocabulary (PR30)
- Regenerate v0.4 reasons
- Reinterpret v0.4 snapshots

### Layering Philosophy
```
┌─────────────────────────────────────┐
│  Future: Intelligence / Optimization │  ← v0.5+
├─────────────────────────────────────┤
│  v0.4: Immutable Explanation Layer  │  ← This spec (frozen)
├─────────────────────────────────────┤
│  v0.3: Intent Classification        │
├─────────────────────────────────────┤
│  v0.2: Constitutional Core          │
└─────────────────────────────────────┘
```

v0.4 is a **permanent layer**, not a temporary step.
