# v0.5 Intelligence Input Contract Charter

**Status**: Active (v0.5)
**Date**: January 2026
**Type**: Input Contract Definition
**Dependency**: PR35 (v0.5 Intelligence Boundary Charter), PR34 (v0.4 Confidence Release Declaration)

---

## Core Declaration

```
v0.5 reads only declared inputs.
Anything else is out-of-contract.

v0.4 is not a training signal.
v0.4 is not a target.
v0.4 is history.
```

---

## 1. Purpose

PR35 established the **boundary** between v0.4 and v0.5: v0.4 is immutable, v0.5 must not modify it.

This charter (PR36) establishes the **input contract**: exactly what v0.5 Intelligence may read, and how it may read it.

### Why an Input Contract?

Without explicit contract:
- Future PRs could gradually expand v0.5's access to v0.4
- Boundary erosion would be undetectable
- v0.4 immutability would be undermined by implicit dependencies

With explicit contract:
- **Allowlist-based**: Only declared inputs are permitted
- **Reviewable**: Any new input requires charter amendment
- **Enforceable**: Violations are detectable (future PR will add guards)

---

## 2. Input Contract (Allowlist)

v0.5 Intelligence may read **only** the following input categories:

### Category A: Market / State Fields

**Definition**: Direct observations from market data or system state.

**Examples** (non-exhaustive):
- Price, volume, spread
- Moving averages, volatility measures
- Orderbook state
- Position size, equity, balance
- Timestamp, tick count

**Usage**: Primary inputs for intelligence decisions.

**Contract**: v0.5 may freely read these fields as they represent current reality.

---

### Category B: Intent / Regime Fields

**Definition**: Classification outputs from v0.3 Intent layer and v0.2 Regime/Policy layer.

**Examples**:
- `intent_primary` (IDLE, SEEK, HARVEST, etc.)
- `intent_reason` (classification explanation)
- `regime` (stable_range, emerging_trend, etc.)
- `base_action` (HOLD, SHIFT, PAUSE)
- `overlay_rule` (ALLOW, REDUCE, FREEZE)

**Usage**: v0.5 may use these as pre-classified state descriptors.

**Contract**: v0.5 may read these fields as deterministic classifications of current state.

---

### Category C: Confidence Snapshot Fields (READ-ONLY)

**Definition**: Historical snapshot fields from v0.4 Confidence layer (frozen, immutable).

**Permitted fields**:
```
confidence_reason          (string, PR27 structure, PR30 vocabulary)
confidence_reason_version  (string, fixed "v0.4")
confidence_reason_generated_at  (string, UTC ISO-8601)
confidence_value           (string, currently empty "")
```

**Usage**: v0.5 may read these as **historical context only**.

**Contract**:
- READ-ONLY reference
- No modification, regeneration, or reinterpretation
- No use as training signal or optimization target

**See Section 3 (Hard Bans) for prohibited uses.**

---

## 3. Hard Bans (Prohibited Uses)

v0.5 Intelligence **SHALL NEVER** do any of the following with v0.4 Confidence fields:

### Ban 1: Use as Training Signal

```python
# ✗ PROHIBITED
def train_model(historical_log):
    for row in historical_log:
        confidence_reason = row["confidence_reason"]
        outcome = row["actual_outcome"]

        # ✗ Using v0.4 as supervised learning label
        loss = measure_confidence_accuracy(confidence_reason, outcome)
        model.update(loss)  # NEVER
```

**Why prohibited**: v0.4 is explanation, not ground truth. Treating it as training signal violates layer separation.

---

### Ban 2: Evaluate Correctness

```python
# ✗ PROHIBITED
def evaluate_confidence_quality(confidence_reason, actual_outcome):
    # ✗ Judging whether v0.4 was "right" or "wrong"
    if confidence_reason == "temporal indicators present":
        was_correct = check_if_prediction_was_accurate(actual_outcome)  # NEVER
        return quality_score  # NEVER
```

**Why prohibited**: v0.4 describes state, it does not predict outcomes. Evaluating "correctness" is a category error.

---

### Ban 3: Score or Featurize

```python
# ✗ PROHIBITED
def extract_confidence_features(confidence_reason):
    # ✗ Converting v0.4 text into numeric features for ML
    features = {
        "has_temporal_indicators": 1 if "temporal indicators present" in confidence_reason else 0,
        "core_signal_count": extract_signal_count(confidence_reason),  # NEVER
        "confidence_score": score_reason(confidence_reason)  # NEVER
    }
    return features  # ✗ v0.4 is not feature input
```

**Why prohibited**: Scoring/featurizing v0.4 treats it as optimization input, violating immutability.

---

### Ban 4: Regenerate or Modify

```python
# ✗ PROHIBITED
from confidence.confidence_reason_builder import build_confidence_reason

def improve_past_confidence(observation):
    # ✗ Calling v0.4 builder from v0.5 to regenerate
    new_reason = build_confidence_reason(observation)  # NEVER
    return new_reason  # ✗ v0.4 is frozen
```

**Why prohibited**: v0.4 snapshots are immutable. Regeneration breaks provenance.

---

### Ban 5: Provide Feedback

```python
# ✗ PROHIBITED
def optimize_confidence_generation(historical_log):
    for row in historical_log:
        confidence_reason = row["confidence_reason"]
        outcome = row["actual_outcome"]

        # ✗ Tuning v0.4 based on outcomes
        if outcome_was_bad:
            suggest_confidence_improvement(confidence_reason)  # NEVER
            tune_v0_4_vocabulary()  # NEVER
```

**Why prohibited**: v0.4 is frozen layer. Feedback from v0.5 to v0.4 violates boundary.

---

### Ban 6: Introduce Evaluative Vocabulary

```python
# ✗ PROHIBITED
def make_decision(current_state, historical_confidence_reason):
    # ✗ Evaluating v0.4 with forbidden vocabulary
    if confidence_is_high(historical_confidence_reason):  # NEVER - "high" is evaluative
        take_aggressive_action()
    elif confidence_is_low(historical_confidence_reason):  # NEVER - "low" is evaluative
        take_conservative_action()
```

**Why prohibited**: v0.4 is non-evaluative. Treating it as "high/low confidence" reinterprets frozen semantics.

## 4. Allowed Uses (Read-Only Consumption)

v0.5 Intelligence **MAY** use v0.4 Confidence fields in the following ways:

### Allowed Use 1: Historical Context Reference

```python

    # Read v0.4 as historical context (read-only)
    recent_confidence_reason = historical_log[-1]["confidence_reason"]
    recent_confidence_version = historical_log[-1]["confidence_reason_version"]

    # Use as context alongside other inputs (not as primary signal)
    decision = intelligence_model.decide(
        current_state=current_state,
        market_data=fetch_market_data(),
        intent=current_intent,
        historical_confidence=recent_confidence_reason,  # Context only
    )
    return decision
```

## 6. Enforcement

### Design Time
- This charter is the reference for all v0.5 Intelligence PRs
- Any input not in allowlist requires charter amendment
- Any prohibited use is grounds for PR rejection

### Implementation Time
- v0.5 code may only import Category A/B/C fields
- v0.5 code may not import v0.4 builders or evaluators
- v0.5 code may not define "confidence score" or similar metrics

### Review Time
- Code review must verify input contract compliance
- Any use of v0.4 as training signal is blocking issue
- Any regeneration of v0.4 is blocking issue

### Future PRs
- PR37+ will add automated guards (lint, import checks, CI)
- Guards will enforce this contract mechanically

---

## 7. Contract Amendment Process

### Adding New Inputs (Category A/B)
If v0.5 needs new market/state or intent/regime fields:
1. Propose field in PR
2. Verify field is not derived from v0.4
3. Add to Category A or B in this charter (amendment)
4. Implement field generation in appropriate layer

### Adding New v0.4 Fields (Category C)
If new v0.4 fields are needed:
1. This requires v0.4 charter amendment (high bar)
2. New fields must maintain immutability guarantees
3. New fields must have version + timestamp provenance
4. Amendment must preserve all v0.4 frozen contracts

**Note**: v0.4 is frozen (PR34), so new fields are highly unlikely.

### Removing Fields from Contract
Fields can be deprecated but not removed retroactively:
1. Mark field as deprecated in charter
2. Provide migration path for existing uses
3. Never remove field from historical logs

## 8. Examples: Contract-Compliant v0.5 Intelligence

### Example 1: Decision-Making with v0.4 Context

```python
def v0_5_intelligence_decision(current_state, historical_log):
    """
    Make intelligence decision using contract-compliant inputs.
    """
    # Category A: Market/State (current reality)
    price = current_state["price"]
    volatility = current_state["volatility"]

    # Category B: Intent/Regime (pre-classified state)
    intent = current_state["intent_primary"]
    regime = current_state["regime"]

    # Category C: v0.4 Confidence (historical context, READ-ONLY)
    if historical_log:
        recent_confidence_reason = historical_log[-1]["confidence_reason"]
        recent_confidence_version = historical_log[-1]["confidence_reason_version"]
    else:
        recent_confidence_reason = ""
        recent_confidence_version = ""

    # v0.5 Intelligence Decision
    # (Uses all categories as READ-ONLY inputs)
    decision = intelligence_model.decide(
        market_state=(price, volatility),
        intent_state=(intent, regime),
        historical_explanation=recent_confidence_reason,  # Context only
    )

    return decision
```

**Compliance**: ✓ Reads only Category A/B/C, treats v0.4 as context, no modification.
